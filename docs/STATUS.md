# 기능별 현재 상태

기준일 2026-10-23. **이 표가 상태의 유일한 기준**이다. README·PLAN·DESIGN은 상태를 따로 적지 않고 여기를 참조한다.

네 칸의 뜻
- **코드**: 구현되어 있다.
- **자동 테스트**: `npm test` 또는 `bash test/ui/run.sh`가 검사한다. 가짜 서버·모의 서비스 기준이다.
- **외부 연동**: 진짜 외부 서비스(AI 제공사, Google/GitHub, 메일 서비스)로 확인했다.
- **배포 환경**: 실제로 배포한 서버(HTTPS, 영구 디스크, 환경변수)에서 확인했다.

외부 연동과 배포 환경 칸은 **아직 전부 ✗** 이다. 이 환경(개발 샌드박스)에서는 외부 서비스에 키를 넣고 호출하거나 서버를 배포할 수 없었다. 확인하려면 `scripts/smoke-providers.js`와 아래 "배포 전 확인" 절차를 쓴다.

**결제 전 비용 정책(임시)**: 플러스는 AI 수·방 예산·일일 크레딧이 제한 없음이다. 공개 전에 `MANAGED_DAILY_CALLS`(서버 키 호출 하루 전체 상한)를 반드시 정하고, 결제를 붙일 때 플러스 한도를 다시 설계한다. 관리형 호출에 "무제한"을 판매하지 않는다(외부 재평가 권고).

## 배포 전 확인 (사람이 해야 하는 것)
1. 키를 넣고 `node scripts/smoke-providers.js` — 쓰려는 제공사마다 5개 항목이 PASS여야 한다.
2. 운영 환경변수(`SESSION_SECRET`, `DATA_DIR`, `COOKIE_SECURE=1`, `PUBLIC_URL`, `ADMIN_TOKEN`, `OPERATOR_NAME`, `CONTACT_EMAIL`)를 넣고 시작 로그에 경고가 없는지 본다.
3. 방을 만들고 → 재배포/재시작 → 방·계정·공유 링크가 남아 있는지 본다.
4. 실제 Google/GitHub 로그인과 메일 인증을 한 번씩 해 본다.
5. 개인정보처리방침·약관에 운영자 정보를 넣고 법률 검토를 받는다.
