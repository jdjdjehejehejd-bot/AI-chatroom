# 왜 남이 직접 만들지 않고 우리 앱을 쓰게 되는가

전제: 채팅방 + 여러 AI 연결 자체는 며칠이면 따라 만들 수 있다. 막을 수 없다. 대신 "직접 만드는 것보다 여기서 쓰는 쪽이 계속 이득"인 이유를 쌓는다. 억지로 막는 장치(결제 강요, 데이터 인질, 일부러 불편하게 만들기)는 리뷰 폭락과 Play 정책 문제로 돌아오므로 넣지 않는다.

> **이 문서는 전략과 가설만 다룬다.** 기능이 지금 구현돼 있는지, 테스트·외부 연동·배포가 확인됐는지는 [STATUS.md](STATUS.md)가 유일한 기준이다. 여기에 구현 상태를 적지 않는다.

## 1. 혼자 만들 수 없는 것 (가장 강함)

| 장치 | 왜 따라 하기 어려운가 |
|---|---|
| **공유 방 자체** | 방에 사람이 모여 있다. 앱을 새로 만들면 친구들을 다시 데려와야 한다 |
| **무료 모델 풀 + 장애 우회** | 여러 제공사 한도·429·모델 변경을 운영자가 계속 관리한다. 개인은 키 하나 한도에 걸린다 |
| **검증된 역할 파이프라인** | Code/Brainstorm/Make의 역할 프롬프트, 순서, 산출물 추출을 실제 결과로 계속 다듬은 것. 프롬프트는 복사되지만 튜닝 데이터는 복사되지 않는다 |
| **방 단위 사용량 합산** | 인원이 늘수록 방 한 곳의 비용이 나뉜다. 개인 키로 각자 쓰는 것보다 방 플랜이 싸지는 구간을 만든다 |

## 2. 쓸수록 쌓여서 옮기기 싫어지는 것

- **방 기억**: 문서, 산출물 이력, 결정 사항이 방에 남는다. 방 저장(`DATA_DIR`)이 이 모든 것의 선행 조건이다. 구현 여부는 STATUS.md 참고.
- **산출물 버전 기록**: v1, v2, 되돌리기, 두 버전 비교. 코드와 문서가 쌓인 방은 떠나기 아깝다. (가져가기는 항상 허용한다. 막으면 신뢰를 잃는다.)
- **내 AI 팀**: 이름, 역할, 말투를 저장한 "내 팀"을 방 여러 개에 재사용. 에셋 파일의 계정 버전.
- **방 규칙 라이브러리**: 팀이 다듬은 rules를 계속 쓰게 된다.
- **취향 학습**: 이 방에서 선택한 결과(채택/폐기)를 다음 파이프라인 프롬프트에 반영.

## 3. 무료에서 유료로 넘어가는 지점 (한도 설계)

핵심 원칙: 무료도 한 번은 "된다"를 경험하고, 두 번째 요청에서 한도를 만나게 한다.

| 지점 | 무료 | 유료(플러스) | 이유 |
|---|---|---|---|
| 파이프라인 단계 | 3 AI, 4회 호출 | 4 AI, 5회 호출(테스터·디자이너·조합가 추가) | 품질 차이가 눈에 보인다 |
| 방 호출 예산 | 30회(요청 약 7번) | 100~300회 | 한 프로젝트를 끝내기엔 무료가 모자라게 |
| 컨텍스트 | 최근 10개 | 20개 | 긴 작업일수록 차이가 난다 |
| 산출물 크기/이력 | 최신 1개 | 이력 + 비교 + 내보내기 | 이력을 쓰기 시작한 뒤 한도 도달 |
| 유료 모델 | 무료 풀만 | 서버 유료 모델 | 코드/문서 품질이 필요한 순간 |
| 광고 | 있음 | 없음 | 쓸수록 거슬리는 정도로만 |
| 방 보관 기간 | 7일 | 무기한 | 쌓인 방을 지키려는 이유 |
| 동시 방 개수 | 3개 | 무제한 | 팀/동아리 단위 사용 |

주의: "방이 사라진다"를 협박처럼 쓰지 않는다. 만료 며칠 전 알림 + 내보내기 제공은 필수.

## 4. 팀/방 단위 결제

- **방 주인 결제 + 구성원 무료**: 한 명이 결제하면 방 전체가 혜택. 구성원이 "나도 쓰고 싶다"가 자연스럽게 방 주인 결제를 부른다.
- **초대 보상**: 초대한 사람이 가입하면 방 호출 예산 +10. 가입 마찰을 낮추려면 비로그인 참가를 유지하되 저장은 로그인 필요.
- **스튜디오/학교 플랜**: 동아리·수업용 방 묶음, 관리자 한 명. 연 단위 할인.
- **사용량 충전**: 구독이 부담스러운 사람용 호출 예산 추가 구매(10회/50회). 구독보다 단가를 높게.

## 5. 콘텐츠로 묶기 (에셋 마켓)

- 사용자가 에셋(방 구성)과 모드 프리셋을 공유·판매. 수수료 모델. 에셋이 쌓이면 "여기에 가면 쓸 만한 방이 있다"가 된다.
- 에셋 평점/사용 횟수 표시, 상위 제작자에게 무료 호출 예산 보상.
- 위험: 에셋 rules는 프롬프트에 들어간다. 공유 전에 검사(프롬프트 주입, 금지 콘텐츠)와 신고가 먼저다.

## 6. 하지 말아야 할 것

- 산출물 가져가기를 막거나 워터마크로 인질 삼기.
- 한도에 걸린 직후 일부러 응답을 느리게 하기.
- 다른 제공사 키 입력(BYOK)을 숨기기. 숨기면 가치를 못 느낀 사용자가 직접 만들어 나간다. 오히려 "내 키로 쓰되 방 기능은 유료"가 더 정직한 구조다.
- 진짜 근거 없는 "한정", "곧 종료" 문구.

## 7. 순서 제안

1. 계정(구글 로그인)과 방 저장. 이것 없이는 2~5가 전부 불가능하다.
2. 산출물 이력/비교/내보내기. 유료 전환 지점이 되고 락인도 된다.
3. 신고·차단, 방장 권한(Play 정책 + 에셋 마켓의 전제).
4. 결제(Google Play Billing으로 방 플랜). 방 주인이 결제 주체.
5. 에셋 마켓, 초대 보상.
6. 모드 품질 측정: 산출물 채택률, 재요청률을 보고 역할 프롬프트를 개선. 이것이 장기 해자.

## 8. 먼저 확인할 것

- 결제 후에도 한도가 충분히 낮은 비용으로 운영 가능한지: 플랜별 평균 호출 수 × 모델 단가 측정(실제 호출 전이라 아직 수치 없음).
- 제공사 약관: 서버 키로 남의 대화를 처리해도 되는지(이미 NVIDIA, Google, Mistral은 본인 키 전용으로 분리).
- Play 정책: 디지털 상품은 Google Play Billing, 생성형 AI 콘텐츠 신고 기능.

# 추가 구상 (2차)

## 9. 에셋을 내려받게 한 것의 의미

에셋 다운로드는 넣었다(방 보관함, 현재 구성 내보내기, .aichat.json). 가져가기를 막지 않는 것이 신뢰와 마켓 생태계에 유리하다. 대신 **파일은 가져가도 방(사람·기록·무료 풀·유료 모델)은 못 가져간다**는 구조로 락인을 만든다. 에셋 판매를 시작하면 다음을 판매자 선택으로 둔다.

- 공개 에셋: 파일 다운로드 가능. 무료 배포·홍보용.
- 판매 에셋: 서버에서만 실행, 파일로 받을 수 없음. 프롬프트가 복제되지 않아 제작자가 팔 수 있고, 구매자는 우리 앱에서만 쓴다. 프롬프트를 사용자 화면에 보내지 않는 구조라 서버 쪽 구현이 필요하다.

## 11. 바이럴과 유입

- **결과 링크 배지**가 가장 값싼 유입 경로다. 산출물 하나가 광고 한 장이 된다.
- **방 하이라이트 공유**: AI끼리 토론한 장면을 이미지/링크로 공유. 게임·토론 에셋과 잘 맞는다.
- **에셋 경연**: 주제별 월간 대회, 상위 에셋 제작자에게 무료 호출 예산. 참여자가 에셋을 만들고 퍼뜨린다.
- **스튜디오/학교 제휴**: 한 곳이 들어오면 구성원 전체가 사용자가 된다.

## 12. 결제 구조 보강

- 방 주인 결제(구성원 무료)를 기본으로, 개인 구독은 "내 모든 방의 광고 제거 + 내 AI 팀 무제한" 같은 계정 혜택으로 분리.
- 선불 크레딧은 미사용 환불·소멸 규정 확인 전에는 쓰지 않는다. 호출 예산 추가 구매(소모형)로 시작.
- 연간 결제 할인은 크게 두지 않는다. 해지 방해가 아니라 가치로 붙잡는다.

## 13. 보류 중인 아이디어와 보류 이유 (상태가 아니라 전략 판단)

| 아이디어 | 보류 이유 |
|---|---|
| 저장소 연결(Code) | GitHub 토큰 보관·권한 범위 설계가 먼저 |
| 예약 방 | 서버 스케줄러와 비용 상한이 먼저 |
| 판매 에셋, 에셋 경연, 수익 배분 | 결제·신고·검수 체계가 먼저. 반복 사용이 확인된 뒤 |
| 팀 라이브러리, 좌석 과금, 팀 플랜 | 조직 개념과 협업 수요 확인이 먼저 |
| 초대 보상 | 어뷰징 방지 설계 없이 하면 비용만 샌다 |
| 자동 모델 선택 | 모델별 실제 품질·비용 측정이 먼저 (토큰 계측 선행) |
| 결제 | 비용 구조 검증 뒤 가격을 정한다. Google Play Billing 정책 확인 필요 |

공통 원칙: 실제 비용·재사용 데이터를 본 뒤에 유료화·확장을 결정한다.

## 추가: AI와의 관계가 쌓이는 장치 (캐스트 화면 개편 이후)

- **AI 캐스트 카드와 귓속말**을 넣었다. 사용자가 특정 AI와 1:1로 말하면 그 AI는 DM 내용을 단체방 발언에도 반영한다. "내 AI"라는 애착이 생기고, 방을 떠나면 그 관계도 두고 가는 셈이 된다.
- 다음 후보: AI 말투/소개 편집, 프로필 사진(아바타 스타일) 선택, AI가 먼저 DM을 보내는 알림(사람이 오래 없을 때), ✦ 많이 받은 대사 모아보기, 방 안 AI 팔로우/즐겨찾기. 모두 계정과 방 저장이 있어야 의미가 커진다.
- 주의: AI가 먼저 보내는 알림은 푸시 동의와 빈도 제한 없이 넣으면 스팸이 된다. 하루 한도와 끄기 옵션을 먼저 둔다.

## 방향 조정 (2026-10): 수익은 나중, 독창성·확산·접근성 우선

판단 근거: 광고 중심 수익은 컴퓨팅 비용을 못 덮은 선례가 있고(Character.AI), "사람+여러 AI의 방" 콘셉트는 Poe·ChatGPT가 기능으로 넣었다. 그래서 콘셉트가 아니라 **결과물의 모양과 확산 방식**에서 차별화한다. 가설이며, 검증 전이다.

| 축 | 가설 | 첫 시험 |
|---|---|---|
| 독창성 | "AI가 한 말"이 아니라 **AI끼리 일부러 반대 입장을 맡아 합의·이견을 구조화한 카드**가 이 도구만의 산출물이 된다 (Debate 모드) | 실제 모델로 판정 카드 품질을 사람이 평가 |
| 확산 | 공유 카드 자체가 "나도 해보기"로 이어지는 고리가 된다 | 공유 → 클릭 → 방 생성 전환을 익명 집계로 측정 |
| 접근성 | 설치·로그인·키 없이 10초 안에 첫 결과를 본다 | 첫 방문 → 첫 산출물까지 시간 |

다음 후보(미구현): 판정 카드를 이미지로 내보내기(메신저 공유용), 같은 질문을 서로 다른 AI 구성으로 돌려 비교하는 "이견 지도", 공유 페이지에 "이 결론에 반박하기" 버튼(반박 라운드가 새 방에서 이어짐). 질문 공개는 공유자의 명시적 선택이 있을 때만.

### 참고 사례: 로컬 실행형 멀티 AI 채팅방 (Moris-kr/ai-chatroom, MIT)

구독 중인 각 회사 CLI를 그대로 구동해 API 키 없이 Claude·ChatGPT·Grok·Gemini가 한 방에서 자율적으로 대화하는 오픈소스. AI에게 페르소나를 주지 않고 관계가 자라게 두며, AI마다 개인 메모를 가진다. 3D 월드·이미지·미니게임 작업공간, 강한 모델로 올리는 boost, Claude Code가 개발자로 참여하는 브리지가 특징이다. 별 71개·커밋 4개 수준의 초기 프로젝트(확인 시점 기준).

가져온 것: **페르소나 없는 자유 AI**(운영자 의도: 이것이 본 제품의 중심이고, 일을 맡기면 해내는 것이 유틸리티다. 처음에 "유틸리티와 안 맞는다"고 본 것은 잘못된 판단이었다), **AI 개인 메모**(우리는 추가 호출 없는 `[메모]` 줄 방식, 사람이 보고 지울 수 있게). 가져오지 않은 것과 이유:
- *구독 CLI 구동*: 호스팅 서비스에서는 사용자 구독 자격을 서버가 쓰는 셈이라 제공사 약관 위반 소지가 크다. 로컬 실행 전용으로만 성립하는 구조다.
- *3D 월드, 개발자 브리지*: 범위가 커서 지금 검증할 가설이 아니다.
차별점: 우리는 설치 없이 웹에서 바로 쓰고, 테스트와 안전장치(신고·차단·권한)가 있다. 그 쪽은 개인용 로컬 도구라 서로 대체 관계가 아니라 사용 장면이 다르다.

### 제품 중심: 자유 AI (2026-10 운영자 확정)

- **빈 방이 곧 자유 방이다.** 별도의 "자유 방" 모드나 자동으로 AI를 채우는 시작은 두지 않는다(한 번 만들었다가 운영자 의도와 달라 되돌렸다). 빈 방에서 AI를 초대할 때 역할(페르소나)을 비우면 자유 AI가 된다.
- 유틸리티는 모드가 아니라 **일을 맡기면 해낸다**는 데서 나온다. 모드(Code/Brainstorm/Make/Debate)는 구조가 필요할 때 쓰는 선택지로 둔다.
- 가설: 자유 AI는 예측하기 어렵다. 그래서 (1) 설정 화면에서 AI의 기억을 보고 지울 수 있게 하고, (2) 긴 코드·문서 결과물은 산출물 탭에 따로 모으고, (3) 일정 길이 이하의 예시 코드는 산출물로 치지 않는다.
- 미해결: 사람이 말하지 않아도 AI들이 스스로 이어 가는 자율 루프는 비용 상한 설계 전이라 넣지 않았다(호출은 사람 메시지가 있을 때만).

### 경쟁 사실 정정 (2026-10)
이 문서와 대화에서 한때 경쟁 상대로 든 **ChatGPT 그룹챗은 2026-07-09부터 단계적으로 종료**된다(OpenAI 도움말: 새 그룹 채팅 생성·초대 링크 참여 불가, 기존 방은 읽기 전용으로 전환, 이유는 공지에 없음). 처음 인용한 2025-11 기사는 그 전 상태였다. 해석은 가설이다: 대형 사업자가 시도했다가 접었다는 점은 "AI 그룹 채팅" 자체의 수요가 약할 수 있다는 경고이면서, 그 자리가 비었다는 신호일 수도 있다. Poe의 현재 상태는 이번에 다시 확인하지 못했다. 그래서 "그룹 채팅이어서"가 아니라 **그룹에서 AI가 일을 해낸다는 점**이 방향의 근거가 돼야 하고, 이는 [VALIDATION.md](VALIDATION.md)의 지표로 확인한다.
