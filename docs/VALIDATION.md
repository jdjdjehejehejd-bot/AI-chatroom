# 검증 계획과 KPI

기능 상태는 [STATUS.md](STATUS.md)가 유일한 기준이다. 이 문서는 **무엇을 어떻게 재서 방향을 판단할지**만 적는다. 수치 목표는 기준선이 생기기 전에는 정하지 않는다.

## 운영 방침
- 지금은 수익보다 **독창성·확산·점유**를 먼저 본다(결제는 나중). 다만 원가는 처음부터 잰다. 비용을 모르면 "점유"를 늘릴수록 손해가 커질 수 있기 때문이다.
- 개인 단위 추적은 하지 않는다. 아래 지표는 모두 익명 집계(`/admin/events`)이고 **방 단위**다. 그래서 "사용자 7일 재방문율"은 못 재고, "방 재방문"으로 대신한다.

## 지표와 이벤트
모든 이벤트는 일별 익명 횟수다. 흐름(flow)은 모드 이름(`code`/`brainstorm`/`make`/`debate`), 모드가 없으면 `free`, 에셋을 적용했으면 `asset`이며 이벤트 이름 뒤에 `.make`처럼 붙은 변형이 함께 쌓인다.

| 보고 싶은 것 | 이벤트 | 정의·주의 |
|---|---|---|
| 첫 결과 도달 | `room_created` → `first_human_msg` → `first_ai_reply` → `first_deliverable` | 방 단위로 단계마다 한 번 |
| 작업 결과 | `run_started` → `run_completed` / `run_failed` / `run_cancelled`, `run_with_deliverable` | 사용자 메시지 하나가 한 실행(자유 방 포함). 완료 = 오류 없이 AI 호출이 1회 이상 일어남, 실패 = 실행 중 AI 오류가 한 번이라도 있었음, 취소 = 방 비움·모드/에셋 교체 등으로 중단. `run_with_deliverable` = 그 실행 중 산출물이 저장됨("끝까지 유효한 결과"). 예산·크레딧 소진은 별도 구분 없음 |
| 산출물 | `deliverable_saved` | 버전 하나가 저장될 때마다(되돌리기 포함) |
| 복사 | `copy_success`, `copy_failed` | 복사 성공 콜백 뒤에만 `copy_success`. 산출물 **버전당 한 번** |
| 다운로드 | `download_clicked` | 클릭이며 파일 저장 성공이 아니다. 채택으로 치지 않는다. 버전당 한 번 |
| 공유 | `result_share_created`, `chat_share_created`, `first_share` | 결과 공유와 대화 공유를 분리. `first_share`와 채택에는 **결과 공유만** 포함 |
| **채택** | `deliv_adopted` | 한 버전에 **복사 성공 또는 결과 공유가 처음 생긴 때 한 번**. "채택한 산출물 수"이며 행동 수가 아니다 |
| **유용성 평가** | `rating.1`~`rating.5` | 산출물 버전당 한 번(정수 1~5). 4~5점을 "쓸 만함"으로 본다 |
| **단일 AI 비교** | `compare_run`, `compare_vote.multi\|single\|tie` | 산출물 아래 "단일 AI 답과 비교"(AI 호출 1회)로 같은 요청을 AI 한 명이 혼자 처리한 답을 받아 나란히 보여 주고 "어느 쪽이 더 낫나요?"를 묻는다. 투표는 버전당 한 번. **핵심 가설(여러 AI가 단일 AI보다 낫다)을 사용자 선택으로 직접 재는 장치**다. 표본이 작으면 결론 내지 않는다. 비교 자체가 비용이라 많이 쓰이면 원가에 잡힌다 |
| 반복 사용(방 기준) | `room_return.d1`, `d2_7`, `d8p` | 방 나이별 하루 한 번. 사용자 유지율이 아님 |
| 제공사 안정성 | `call_ok.<제공사>`, `call_err.<제공사>`, `ms.<제공사>` | 오류율, 평균 지연 |
| 원가 | `tok_in/tok_out/cost_micro/cost_unpriced/tok_missing.<제공사>` | 아래 "비용 상태" 참고 |

서버는 클라이언트가 보내는 행동 신호를 **허용 목록·존재하는 산출물 버전·버전당 한 번**으로만 받는다. 연결당 메시지 속도 제한(5초 8개)도 적용된다.

### 비용 상태 (관리자 화면에 표시)
- `no_real_calls`: 실제 제공사 호출이 0건. 비용 0이 아니라 **측정 데이터 없음**이다(데모 모드 포함).
- `fully_priced`: 호출이 있고 모두 단가가 있으며 usage가 보고됨.
- `incomplete`: 단가 없는 호출, usage 미보고, **또는 실패 호출(`failedCallsUnverified`)이 하나라도 있음**. 실패 호출은 제공사가 usage를 주지 않으면 비용에 잡히지 않으므로 보수적으로 미확인 처리한다(401처럼 과금이 없는 실패도 포함해 엄격한 쪽). 비용은 **과소 값**이며 이 상태에서는 가격·유료화를 판단하지 않는다. 채택 1회당·유용(4~5점) 1건당 비용은 이 총비용을 나눈 값이다.

### 작업(run) ID를 두지 않는 이유
호출·결과·평가를 한 작업 ID로 이어 붙이면 작업 단위 원가를 정확히 알 수 있지만, 방·사람과 연결될 수 있는 식별자를 분석 기록에 남기게 된다. 지금은 집계 수준(총비용 ÷ 채택/유용 결과 수)으로만 계산한다. 작업 단위 원가가 꼭 필요하면, 파일럿 참가자의 동의를 받은 뒤 임시 ID를 도입한다(아직 안 했다).

한계: 같은 방의 여러 사람은 한 방으로 센다. 방을 지우고 새로 만들면 새 방이다. 서버 재시작 전에 만들어진 방은 깔때기 단계가 한 번 더 셀 수 있다.

## 관리자 화면 요약
모든 비율 옆에 분모와 분자를 `(n=a/b)`로 함께 표시한다(표본이 작은 퍼센트를 과신하지 않기 위해).

`/admin` → "집계 보기" 위쪽에 깔때기 비율, 실행 완료율, 산출물 버전 수, 채택 수와 비율, 복사 성공/실패, 다운로드 클릭, 유용성 평가와 4~5점 비율, 방 재방문, 제공사 오류율, 총 비용, 채택 1회당·유용 1건당 비용, **비용 상태**가 나오고, 그 아래 **흐름별 표**(free/asset/code/brainstorm/make/debate)가 있다.

## 자유 AI vs 모드 분리 측정
관리자 화면의 흐름별 표가 (a) `free`와 (b) 모드별 시작 수·완료율·산출물 버전·채택·평가를 따로 보여 준다. 분모(시작 수)가 작으면 숫자로 결론 내지 않는다.

## 순서(제안, 일정은 예측이 아님)
1. **실제 AI로 끝까지**: 키를 넣고 `scripts/smoke-providers.js`, 배포 전 확인 절차(STATUS.md)를 통과한다. 이것이 없으면 아래 수치는 모두 데모 값이다.
2. **소수 사용자에게 열기**: 지인 수십 명. 사용 한도와 비용 알림을 켠 상태로. 깔때기 단계별 이탈 지점을 본다.
3. **반복 여부 보기**: 방 재방문, 산출물이 생긴 방의 채택 비율.
4. **원가와 가격**: 성공한 결과 1건당 비용을 계산하고, 그 뒤에 가격 실험을 한다.

## 진행·수정·중단 기준(방향)
- 진행: 사람들이 같은 방으로 돌아오고(재방문), 산출물이 복사·저장·공유로 이어지고, 성공 결과 1건의 원가가 감당 가능하다.
- 수정: 처음엔 쓰는데 돌아오지 않으면 사용 사례를 좁힌다. 돌아오는데 원가가 크면 모델 배분·호출 수·한도를 조정한다.
- 재포지셔닝: 충분히 열어 본 뒤에도 첫 결과 도달과 재방문이 모두 낮으면 기능 추가가 아니라 가설을 바꾼다.

## 가장 먼저 답해야 할 질문
"자유 AI에게 일을 맡기면 쓸 만한 결과가 나오는가." 이것은 데모가 아니라 실제 모델로 해 봐야 안다.

## 파일럿 운영 양식 (외부 재평가 제안 반영)
아래 통과 기준은 **제안값**이다. 산업 표준이나 통계적 보장이 아니며 표본이 작으므로 정성 피드백과 함께 해석한다. 분석 기록에는 사용자 이름·대화 원문·API 키를 넣지 않는다.

| 영역 | 제안 통과 기준 | 실패 시 |
|---|---|---|
| 운영 안정성 | 실제 제공사 한 곳 이상에서 스모크 5개 통과, 작업 40~60건의 호출 성공률 ≥95%, 재시작 복원 확인 | 원인을 모델·인증·한도·저장으로 나누고 규모를 키우지 않는다 |
| 결과 유용성 | 평가가 있는 결과 중 60% 이상이 4~5점(최소 30건 평가 목표) | 낮은 흐름의 과제 범위를 좁히고 프롬프트·형식을 고친다 |
| 채택 | 산출물이 생긴 작업 중 30% 이상에서 복사 성공 또는 결과 공유 | 품질·내보내기 편의·첫 결과까지의 시간을 본다 |
| 재방문 | 관찰 기간이 충분한 방 중 20% 이상이 다른 날 재사용(방 기준) | 반복 이유를 재설계한다 |
| 비용 | 비용 상태 `fully_priced` 비율 목표 ≥95%, 유용 결과 1건당 비용 계산 가능 | 가격·모델·호출 수를 조정하고 `incomplete`인 동안 유료화 판단을 보류 |
| 지불 의사 | 구체적 가격을 제시했을 때 반복 사용 의사와 지불 이유를 설명하는 사용자가 있음 | 개인 키 사용·팀/동아리·특정 작업 가치 등 다른 가설 확인 |
| 안전·법적 | 개인정보처리방침·약관·운영자 연락처 완성, 신고·삭제 절차 시험, 비밀·개인정보 노출 중대 이슈 0건 | 공개 확대·마켓·결제를 보류 |

6/10 "사업화 준비도"의 의미는 매출·제품-시장 적합성이 입증됐다는 뜻이 아니라, 제한된 사용자에게 실제 AI를 안정적으로 제공하고 유용성과 비용을 측정해 다음 투자 판단을 할 최소 근거가 생겼다는 뜻이다(외부 평가의 정의를 그대로 따른다).

### 작업마다 한 줄 기록(수동)
흐름(free 또는 모드), 과제 유형(코드·HTML·문서·아이디어), 산출물 생성 여부와 완료·오류·취소, 유용성 1~5점, 한 행동(copy_success·download_clicked·share), 제공사·호출 수·지연·오류 종류, 토큰 보고·가격 적용 여부. 같은 방의 다른 날 재사용 여부(방 기준).

### 사용자 인터뷰 5문항
1. 방금 해결하려던 실제 작업은 무엇이었나?
2. 결과물 중 실제로 쓸 수 있었던 부분과 쓸 수 없었던 부분은?
3. 복사·다운로드·공유 중 실제로 한 행동과 이유는?
4. 평소 쓰는 AI 도구와 비교해 시간을 절약했거나 더 나아진 점은?
5. 제시된 구체적 가격에서 반복 사용할 생각이 있는가? 없다면 가장 큰 이유는?

### 매주 남길 결정 기록
무엇이 증명됐나(실제 호출·유용 결과·채택·재방문·비용) / 무엇이 아직 불확실한가(표본·누락·외부 연동 미검증, 추정은 사실과 분리) / 다음 주 한 가지 우선순위(가장 큰 이탈 또는 비용 문제 하나와 완료 기준) / 결정(확장·수정 후 재시험·방향 변경과 근거).
