What it does

Debugging a failure from a device log usually starts with the same chores: mixed timestamp formats, repeated lines, stack traces split from their error, and no clear point where the story begins. This tool does that first pass for you.

  • Reads ISO timestamps, Android logcat, syslog and epoch-seconds lines and sorts everything by time
  • Detects log levels (INFO, WARN, ERROR, FATAL)
  • Keeps stack-trace lines attached to the error they belong to
  • Collapses repeated lines (shown as x37)
  • Groups similar errors into patterns: timeout after 8946ms and timeout after 6457ms count as one
  • Marks long silent gaps as possible reboot, hang or disconnect points
  • Exports a Markdown report and an Excel-ready CSV

FAQ

Is my log uploaded anywhere?

No. The page does all processing in your browser with JavaScript. The log text is not sent to any server.

How do I find where a device rebooted?

Look for the "gap" markers in the timeline. A long silence right before the first error, followed by a boot message, often indicates a reboot or hang. Lower the silence threshold to see shorter gaps.

What if my log format is not recognized?

Lines without a recognizable timestamp are attached to the previous event (useful for stack traces) or skipped if they come first. The summary shows how many lines were skipped.

How large a file can I use?

It depends on your browser and device. Files of a few tens of megabytes usually work; the timeline view shows the first 3000 events while the downloads contain everything.

Is there a command-line version?

Yes, a dependency-free Python version is available from the latest release.
